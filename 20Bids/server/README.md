# 20Bids Backend API

> **Stock recommendation engine with automated trading capabilities.**  
> This backend serves daily stock recommendations generated by statistical models (R), enriches them with real-time market data (Polygon.io), provides analytical tools (TP/SL optimization, equity curves), and automates order execution via Interactive Brokers (IBKR).

## 🔌 API Endpoints

**Base URL:** `https://two0bids-api.onrender.com/api`  
**Port:** `3001` (local dev)

### Core Data Endpoints (PUBLIC - no auth required)

#### `GET /api/recommendations?date=YYYY-MM-DD`
Returns recommendations for a given date. If today, enriches with real-time Polygon prices.

```json
// Response: Array of Recommendation objects
[
  {
    "id": "uuid",
    "symbol": "AAPL",
    "name": "Apple Inc.",
    "price": 185.50,
    "open": 184.20,
    "high": 186.30,
    "refPrice1020": 184.80,
    "probability": "High",
    "probabilityValue": 88,
    "volume": 52000000,
    "sector": "Technology",
    "changePercent": 1.2,
    "userTag": "green"   // from Tag model, if any
    // ... all Recommendation fields
  }
]
```

#### `GET /api/dates`
Returns all dates with available recommendations.
```json
// Response: Array of ISO date strings
["2026-04-25T00:00:00.000Z", "2026-04-24T00:00:00.000Z", ...]
```

#### `GET /api/prices`
Returns real-time prices for today's recommendations (via Polygon.io).
```json
{
  "AAPL": { "price": 185.50, "change": 1.2, "volume": 52000000 },
  "MSFT": { "price": 420.30, "change": -0.5, "volume": 28000000 }
}
```

#### `GET /api/indices`
Returns major market indices (SPY, QQQ, DIA, IWM, VIX).
```json
[
  { "symbol": "SPY", "name": "S&P 500", "price": 520.5, "change": 0.8 }
]
```

#### `GET /api/health`
```json
{ "status": "ok", "version": "1.0.3" }
```

### Analytics Endpoints

#### `GET /api/stats/analysis`
**Main analytics engine.** Returns equity curve, distribution, sector breakdown, seasonality, etc.

| Param | Type | Default | Description |
|-------|------|---------|-------------|
| `tp` | float | 100 | Take profit % cap |
| `sl` | float | 100 | Stop loss % cap |
| `minVol` | float | 0 | Min volume filter |
| `minPrice` | float | 0 | Min price filter |
| `minProb` | int | 0 | Min probability filter |
| `startDate` | ISO string | - | Start date filter |
| `endDate` | ISO string | - | End date filter |

```json
// Response
{
  "equityCurve": [{ "date": "2026-01-15", "return": 1.5, "equity": 15.3, "drawdown": -2.1 }],
  "distribution": [{ "name": "0-1%", "value": 45 }],
  "seasonality": [{ "name": "Monday", "avgReturn": 0.8, "winRate": 55 }],
  "sectorBreakdown": [{ "sector": "Technology", "avgReturn": 1.2, "winRate": 60 }],
  "topTickers": [{ "symbol": "AAPL", "avgMvso": 2.1, "winRate": 70, "count": 15 }],
  "tradeReturns": [{ "date": "2026-01-15", "return": 1.5, "probability": 85 }],
  "riskMetrics": { "profitFactor": 2.3, "maxDrawdown": -5.2, "totalReturn": 45.3 }
}
```

#### `GET /api/stats/optimization`
TP/SL grid search optimization. Returns heatmap data for all TP×SL combinations.

#### `GET /api/stats/mvso-history`
Historical MVSO (Max vs Open) data for accuracy tracking.

### Tags & User Preferences

#### `POST /api/tags`
Set/remove a color tag on a ticker.
```json
// Request
{ "symbol": "AAPL", "color": "green" }  // color = null to remove
```

### Data Ingestion

#### `POST /api/recommendations/upload`
Upload CSV files with recommendations. **Requires `x-api-key` header.**
- Accepts multipart form with `files` field
- CSV format: `Ticker, date, open, voltotal, prob_media`
- Auto-enriches with Polygon.io data (daily stats, intraday stats)

#### `POST /api/external/ingest`
**This is how the daily picks actually get in.** An R script on an AWS RStudio
instance POSTs the day's rows here. See `../DEPLOYMENT_GUIDE.md` section 6 for
the R code, the correct host (`two0bids-api.onrender.com` — note the "two") and
how to test the key without writing anything.

Requires the `x-api-key` header, matched against `UPLOAD_API_KEY`. Upserts on
`(symbol, date)`, so re-sending a day updates instead of duplicating.

If this returns 401, that day has no picks and **nothing anywhere raises an
alarm** — there is no error monitoring and no alert for a session with zero
rows. Worth fixing.
```json
// Request: Array of recommendation objects
[{ "symbol": "AAPL", "date": "2026-04-25", "high": 186, "refPrice1020": 184.8, ... }]
```

### Auth Endpoints (`/api/auth/...`)

| Method | Endpoint | Auth? | Description |
|--------|----------|-------|-------------|
| POST | `/api/auth/register` | No | Create account (`email`, `password`, `name`) |
| POST | `/api/auth/login` | No | Login, returns JWT token |
| GET | `/api/auth/me` | Yes | Get current user profile |
| PUT | `/api/auth/profile` | Yes | Update profile (`name`, `avatarUrl`, `password`, `settings`) |
| POST | `/api/auth/avatar` | Yes | Upload avatar (multipart, `avatar` field) |

**Auth:** JWT Bearer token in `Authorization: Bearer <token>` header. Tokens expire in 7 days.

### Trading Automation

#### `GET /api/trading/config`
Get current trading configuration.

#### `PUT /api/trading/config`
Update trading parameters (TP, SL, maxStocks, enabled, etc.).

#### `GET /api/trading/logs`
Get last 100 trade execution logs.

#### `GET /api/trading/positions`
Get current IBKR positions and open orders (requires local IBKR connection).

### Admin Endpoints

| Method | Endpoint | Description |
|--------|----------|-------------|
| POST | `/api/admin/refresh-day?date=YYYY-MM-DD` | Re-fetch Polygon data for a date |
| POST | `/api/admin/backfill-1020` | Backfill all 10:20 reference prices |
| GET | `/api/admin/diagnose-ticker?symbol=X&date=Y` | Debug data for a specific ticker |

## ⚙️ Environment Variables

```env
# Database (required)
DATABASE_URL="postgresql://user:pass@host/dbname"

# Market Data (required for price features)
POLYGON_API_KEY="your_polygon_key"

# Auth (required)
JWT_SECRET="your-secret-key"

# Data ingestion + admin endpoints (REQUIRED).
# The variable is UPLOAD_API_KEY. This file used to call it INGEST_API_KEY,
# which does not exist anywhere in the code — if you set that name, nothing
# was protected. It guards /api/external/ingest (the daily pick load from the
# R script on AWS), /api/recommendations/upload, the /api/admin/* routes, the
# /api/trading/* routes, the push broadcast and the Stripe sub reconciler.
UPLOAD_API_KEY="a real random secret, never the dev- default"

# Billing (REQUIRED — without these nobody who pays becomes PRO)
STRIPE_SECRET_KEY="sk_live_..."
STRIPE_WEBHOOK_SECRET="whsec_..."   # must be from the SAME Stripe environment
RC_WEBHOOK_AUTH="the RevenueCat webhook shared secret"
# STRIPE_PRICE_ID / STRIPE_PAYMENT_LINK are optional (one of them is needed)
# STRIPE_PAYMENT_LINK_TEST must NOT be set in production — it is ignored there
# by code, but do not keep it around.

# Password reset email (optional; without it the flow LOOKS fine, sends
# nothing, and leaves the reset code in the Render logs)
RESEND_API_KEY="re_..."
EMAIL_FROM="..."

# Telegram Notifications (optional — only used by the auto_trader script)
TELEGRAM_BOT_TOKEN="your_bot_token"
TELEGRAM_CHAT_ID="your_chat_id"

# Environment. Set this explicitly in Render: src/config/env.ts only enforces
# the required list when NODE_ENV === 'production'. Without it, a missing
# secret silently becomes a dev placeholder.
NODE_ENV=production

# Server
PORT=3001
```

> `src/config/env.ts` validates all of this at boot and **throws** in
> production if a required variable is missing or still holds a dev
> placeholder. That is deliberate: a server that will not start is better than
> one running on a secret published in this repository.

## 📱 Integration Guide: New Mobile App

To build a new mobile app (React Native, Flutter, Swift, etc.) that uses this same backend:

### 1. Connect to the API
```
Base URL: https://two0bids-api.onrender.com/api
```

### 2. Core Flow
```
1. GET /api/dates              → Get available dates
2. GET /api/recommendations?date=...  → Get stocks for a date
3. GET /api/prices             → Real-time price updates (poll every 30s)
4. GET /api/indices            → Market overview
5. GET /api/stats/analysis     → Analytics/backtesting
```

### 3. Auth Flow
```
1. POST /api/auth/register     → Create account
2. POST /api/auth/login        → Get JWT token
3. Store token securely (Keychain/SecureStorage)
4. Send in header: Authorization: Bearer <token>
5. GET /api/auth/me            → Verify token / get profile
```

### 4. Key Data Types (TypeScript reference)
```typescript
interface Recommendation {
  id: string;
  symbol: string;
  name: string;
  date: string;            // ISO date
  price: number;           // Current price
  open: number;            // Opening price
  high: number;            // Daily high
  refPrice1020: number | null;  // 10:20 AM reference
  changePercent: number;
  volume: number;
  relativeVol: number;
  marketCap: number;
  sector: string;
  probability: string;     // "High" | "Medium" | "Low"
  probabilityValue: number; // 0-100
  stopLoss: number;
  priceTarget: number;
  thesis: string;
  sentiment: string;       // "Bullish" | "Neutral" | "Bearish"
  rsi: number;
  beta: number;
  userTag?: string;        // Color tag set by user
}
```

### 5. Important Notes
- The API is on **Render free tier** — first request after inactivity takes ~30s to wake up
- No rate limiting currently implemented
- Real-time prices come from Polygon.io (15-min delayed on free tier)
- IBKR trading features only work when connected locally (not from mobile)
- All dates are in UTC; the frontend handles timezone display

### 6. Reference Implementation
See `src/api/client.ts` in the frontend — it contains working implementations of all API calls used by the current web app.
